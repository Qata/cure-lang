## 1. The gate (from `2026-07-12-macro-facility-program.md` / REMAINING-WORK §5.3)

> "auto-hygiene renames template binders with no annotation; `<capture>` still
> binds into caller scope on demand; full suite green."

Concretely: in a Tier-2 `becomes` template, an identifier in an **ordinary
lexical binding position** that the template introduces (a `let`/assignment LHS,
an expression-position lambda parameter, a match-arm pattern variable, a
comprehension binder) must be gensym'd automatically — **without** `<fresh …>` —
together with every reference the template makes to that binder, so a template
binder can never capture use-site material and vice versa. `<capture Name>` is
the on-demand opt-out.

## 2. Current state (grounded, verified in tree)

- `<fresh Name>` parses only as an explicit prefix marker in the `:lt` window at
  `parser.ex:2041-2046` → `{:fresh_name, meta, name}`.
- `expand_template_rule` (`parser.ex:1142-1144`) runs `freshen(template, state,
  true, bindings)` **before** `subst_holes`, so use-site material is never
  freshened. **This ordering is load-bearing and is the crux of §4's boundary.**
- `freshen/4` (`parser.ex:1270`) collects `collect_fresh_names/1` (ONLY
  `{:fresh_name,…}` markers), mints one gensym per name via `mint_gensym/3`
  (collision-avoidance vs. `collect_used_names(bindings)` — the gap-(b) fix), and
  rewrites via `apply_freshening/4`.
- `apply_freshening/4` (`parser.ex:1381+`) is a **flat, tuple/list-only** rewrite:
  it recurses into `{t, meta, ch}` when `is_list(ch)` and into list values, and
  **falls through every other shape untouched** — in particular **raw Elixir
  maps** and **string children** (`apply_freshening_value/4`,
  `parser.ex:1416-1422`; same for `collect_fresh_names_*`). It has **no notion of
  lexical scope** — correct today only because the sole freshened names come from
  explicit unique markers.

**Binder shapes a template can contain** — GROUND-TRUTHED against real parser
output (probe `scratchpad/binder_probe.exs`; exact tuples below):
- **`let … in` (expression form)** → `{:block, meta, [{:assignment, [let: true],
  [{:variable, _, "x"}, value]}, body]}` (`parse_let/1`, `parser.ex:3177-3230`).
  The binder is the LHS `{:variable, _, "x"}`; scope is the `body` sibling.
  **Destructuring-`let` is NOT a shape** — the probe proved `let {a, b} = p in …`
  **fails to parse** (`unexpected_token :lbrace`); the LHS is always a bare
  `{:variable}`. (Multi-binder patterns arrive only via **match** arms, below.)
- **block-form `let` (no `in`)** → the `{:assignment, …}` appears as a child of an
  enclosing `{:block, meta, [assignment, sibling₁, …]}`; the binder scopes the
  **following siblings**, not a nested body. (SERIOUS 2 — needs its own frame rule,
  §5 Task 3.)
- **match arm** → `{:pattern_match, meta, [scrutinee, arm₁, …]}` where
  `arm = {:match_arm, [pattern: p], [body]}` (pattern in **meta**,
  `parser.ex:3594`). Every `{:variable, _, name}` **leaf** of `p` (e.g. the `x` in
  `Some(x)` = `{:function_call, [name: "Some"], [{:variable, _, "x"}]}`) is a
  binder scoping `body`. **Guarded arm** → `{:match_arm, [pattern: p, guard: g],
  [body]}` — `g` sits in **meta** and references the pattern binders, so the
  rename frame must span the guard too (MINOR 1). With-rematch arms stash
  `:parent_patterns` in meta (`parser.ex:3707-3744`); the existing
  `collect_fresh_names_meta` comment (`parser.ex:1355-1358`) already documents that
  markers hide in meta.
- **comprehension/generator** → `{:generator, [], [pattern, collection]}`
  (`parser.ex:2822-2875`) — `pattern` binds names. (Surface syntax UNPROBED; Task 0
  confirms during execution before relying on it.)
- **expression-position anonymous lambda** → `{:lambda, [params: [{:param, [],
  "y"}]], [body]}` — `params:` meta is a list of `{:param, meta, string}` tuples;
  body is real AST. → **IN scope**, dedicated `:params`-slot string-child rename
  case (§5 Task 3).
- **single-clause named fn-def in expression** → `{:function_def, [name: "g",
  params: [{:param, [type: …], "x"}], …], [body]}` — params in a meta **list** of
  `{:param, meta, string}`, body **real AST**. **This is renamable exactly like the
  lambda shape** (all tuples/keyword-lists; only the `{:param, _, string}`
  string-child needs the dedicated case). → **IN scope** (v3 fix; closes the
  `syntax withf <e> becomes fn f(x:Int) = e` capture, SERIOUS 1).
- **map-shaped signature binders — OUT (§4):** (a) **multi-clause `def`/`fn`** →
  `:clauses` meta is a list of raw **maps** `%{params:, guard:, body:}`
  (`parser.ex:4338/4407`); (b) **`becomes lift module` callbacks** →
  `parse_lift_callback` returns a **map** with `params: [{:param, meta, name}]` and
  `parameter_names` derived by verbatim string at `parser.ex:5914`, body a
  delayed-raw hole (`parser.ex:5903-5922`). Both are unwalked maps (§4).

## 3. Design fork (prose; RECOMMEND lower-risk Option B — review confirmed sound)

**Option A — full set-of-scopes (Flatt / Racket).** Uncopyable scope marks on
every identifier; hygiene falls out of scope-set resolution. The spec-named
ideal, and the model needed for hygiene that survives **serialization across
module boundaries** (SP5.2 cross-module macro import). **Risk: HIGH** — changes
the identifier representation across the parser and every consumer; large
rewrite; broad test churn.

**Option B — template-scoped binding-position auto-freshening (RECOMMENDED).**
Keep the string-gensym substrate; auto-discover ordinary binder names from
binding positions and replace the flat `apply_freshening` with a **scope-aware
walk** (rename frames pushed at each binding form; rename a binder + only the
references it lexically binds; honor shadowing; leave free refs — holes /
caller names — untouched), reusing `mint_gensym`'s collision-avoidance +
hole-exclusion. `<capture Name>` opts a binder out. Same observable gate,
lower risk.

**Soundness of the fork — CONFIRMED by Stage-3 review (`a23355a3`).** The
reviewer tried and **could not** construct a single-module program where Option
B diverges from set-of-scopes given a correctly-implemented walk: `fresh_counter`
is a single **globally-monotonic** counter threaded through parser state
(`parser.ex:1290-1299`), so two mints — across nested expansion, sibling
invocations, or an inner expansion flowing into an outer hole — **cannot**
collide by construction (not by luck); and `collect_used_names` (gap-(b))
already defends caller spoofing within an invocation. The two *exploitable* holes
A was invoked for are already closed. A's only strictly-greater power
(serializable cross-module scope identity) belongs to **SP5.2**. **Decision:
implement B now; record A as the deferred upgrade, revisited iff SP5.2 needs
serializable scope identity.** B's scope-aware walk is exactly where A would
later slot in — no rework wasted.

## 4. SCOPE BOUNDARY (the FATAL finding, resolved) — what auto-hygiene does and does NOT touch

Auto-hygiene applies to a binder **iff** (i) it sits in the **ordinary
expression grammar** (proper AST tuples/keyword-lists), AND (ii) its **scope body
is real AST at freshen time**. This is precisely the set the tuple/list walk can
reach and rename soundly. The discriminator is **tuple-vs-map**, not
"expression-vs-signature": a single-clause fn-def's params live in a meta
**keyword-list** with a real-AST body and ARE renamable; only genuinely
**map-shaped** structures are unreachable and stay out.

**IN scope** (this slice):
- `let`/assignment binders — expression-form (`{:block, [assignment, body]}`,
  body scope) **and** block-form (`{:assignment}` scoping following siblings of
  the enclosing `{:block, …}`, SERIOUS 2);
- match-arm pattern binders — **every `{:variable}` leaf** of the arm pattern,
  scoping both the arm `body` **and** the `guard:` in the arm's meta (MINOR 1);
- with-rematch `:parent_patterns`;
- comprehension/generator binders;
- **expression-position anonymous-lambda params** (`{:lambda, [params: [{:param,
  _, s}]], [body]}`) **and single-clause named-fn-def params** (`{:function_def,
  [params: [{:param, _, s}], …], [body]}`) — both are meta keyword-lists of
  `{:param, _, string}` over a real-AST body; the `{:param, _, string}`
  string-child gets the dedicated rename case (SERIOUS 1 fix — this is what closes
  `syntax withf <e> becomes fn f(x:Int) = e` capturing a use-site `x`).

**OUT of scope — DEFERRED, documented, and POSITIVELY TESTED as a no-op**: the
**map-shaped** family-signature binders only — the `becomes lift module`
`:callbacks` maps and multi-clause `:clauses` maps and their `{:param, _, name}`
entries. **Why they are excluded, not merely unhandled:**
1. They live in raw Elixir **maps**, which the freshening recursion never walks —
   so today they are untouched, and this slice **must keep them untouched**.
2. Specifically for **`becomes lift module` callbacks**, the callback **body is a
   delayed-raw hole** resolved *after* `freshen` (inside `subst_holes` via
   `subst_lift_module_value`/`resolve_delayed_raw`, `parser.ex:1577-1622`), and it
   binds its signature params by **verbatim name-match** against
   `callback_context.parameter_names` (`parser.ex:5914`). Renaming such a param at
   freshen time therefore **cannot** propagate into a body that is not yet AST — it
   would silently break every `%[:reply, :ok, state]` / `%[:noreply, state]` clause
   across `Std.Actor/Fsm/Supervisor/App` (`lib/std/actor.cure:77-148` et al.). This
   is a signature-binds-body closed unit under the family expander's control, not a
   caller-capture hazard. (This reason is specific to the lift-family path; the
   plain single-clause `function_def` above has a real-AST body and does NOT share
   it — hence its move IN.)
3. `<capture>` cannot even be *written* on such a map param: `parse_typed_params`
   (`parser.ex:4572-4616`) reads a raw identifier token with no `parse_expr` hook
   for a `<capture …>` prefix. (The IN-set lambda/fn-def params reach the walk as
   proper `{:param, _, string}` tuples and need no such marker to be renamed.)

**Consequence for the design:** the walk **must NOT add map-walking**. Keeping
the recursion tuple/list-only is what makes the map-shaped family-signature
binders a guaranteed no-op while the tuple-shaped single-clause params ARE reached.
Hygiene for the map-shaped family-signature params is a **separate follow-on
concern** (tie to family/OTP hygiene, plausibly folded with SP5.2 or its own
slice) — named here as a known limitation, out of SP5.3's DONE bar.

### Task 1 — RED fixtures (`test/cure/compiler/macro_hygiene_test.exs`)
All initially red, behavioral assertions on expanded output:
1. **auto-capture-avoidance:** `syntax m becomes let acc = 0 in acc` where the
   caller has its own `acc` — template `acc` is gensym'd, distinct.
2. **shadowing:** `becomes let x = 1 in let x = 2 in x` — trailing `x` → inner
   gensym; the two binders get distinct gensyms.
3. **block-form `let` sibling scope (SERIOUS 2):** `becomes` a no-`in` block-form
   `let tmp = 0` with a **trailing statement** referencing `tmp` — `tmp` is
   auto-freshened and the trailing sibling's reference tracks the gensym.
4. **free-var passthrough (gap-(a) regression):** a plain template reference that
   is a **hole** is still substituted, not freshened.
5. **`<capture Name>` opt-out:** `becomes let <capture done> = true in done` —
   `done` NOT freshened; binds into caller scope.
6. **expression-lambda param** and **match-arm pattern var** auto-freshened;
   **guarded arm (MINOR 1):** `becomes match … Some(x) when x > 0 -> x` — the
   guard reference to `x` is renamed to the same gensym as the pattern binder.
7. **single-clause named-fn-def capture (SERIOUS 1):** `syntax withf <e> becomes
   fn f(x:Int) = e` invoked as `withf(x + 1)` where the use-site `x` flows through
   hole `<e>` — the template's `fn f(x:Int)` param is gensym'd, so the use-site
   `x` in the body is NOT captured by it (stays the caller's `x`).
8. **OTP no-op (positive boundary lock):** a `becomes lift module` template with a
   `callback` signature — assert the map-shaped signature param name is
   **unchanged** after expansion (auto-hygiene is a no-op on §4's OUT set). This
   pins the boundary so a future executor can't silently "generalize" into it.

### Task 2 — binder discovery (`collect_binder_names`, IN-set only)
Identify template-introduced binder names by AST shape for the §4 IN set —
**every `{:variable}` leaf** of assignment-LHS / match-arm / generator /
with-rematch patterns, plus the `{:param, _, string}` string-children of
**expression-position lambda AND single-clause named-fn-def** `params` meta lists
— EXCLUDING hole names and `<capture>`-marked names, and **never descending into
`:callbacks`/`:clauses` maps** (assert this: the map-shaped OUT set stays a no-op).

### Task 3 — scope-aware freshening walk (UNIFIED with `<fresh>`)
Replace the flat `apply_freshening/4` with a scoped walk carrying a stack of
rename frames. At each binding form, mint gensyms (via existing `mint_gensym/3`)
for its non-`<capture>` binders, push a frame over the correct scope, rewrite
binder + the references it binds, pop on exit; free refs fall through (holes
handled as today). **Frame shapes (ground-truthed, §2):**
- **expression-form `let`** (`{:block, [assignment, body]}`) — frame spans `body`.
- **block-form `let`** (`{:assignment}` as a `{:block, […]}` child) — frame spans
  the **following siblings** in the enclosing block, not a nested body (SERIOUS 2).
- **match arm** (`{:match_arm, [pattern: p (+ guard: g)], [body]}`) — frame spans
  **both the `body` AND the `guard:` term in meta** (MINOR 1); binders = every
  `{:variable}` leaf of `p`.
- **lambda / single-clause named fn-def** — frame spans `[body]`; binders are the
  `{:param, _, string}` string-children of the `:params` meta list, renamed via a
  **dedicated `:params`-slot string-child case** (MINOR 2) — the only place a bare
  string in meta is treated as a binder occurrence.
**`<fresh Name>` markers fold INTO this walk** as a frame spanning "rest of
template" (matching today's template-global behavior) — ONE unified pass, explicit
precedence, so a template mixing `<fresh x>` with an auto-discovered `let x` has a
defined result (Task 5 locks this with a test). **Maps are still not walked** (§4)
— that is the invariant keeping the OUT set a no-op.

### Task 4 — `<capture Name>` marker

`{:variable}` the walk leaves untouched. (Applies only to expression-grammar
binders; §4 OUT binders are unreachable by design and need no marker.)
