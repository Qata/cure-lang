## 1. The gate (from `2026-07-12-macro-facility-program.md` / REMAINING-WORK §5.3)

> "auto-hygiene renames template binders with no annotation; `<capture>` still
> binds into caller scope on demand; full suite green."

Concretely: in a Tier-2 `becomes` template, an identifier in a **binding
position** that the template itself introduces (a `let`/assignment LHS, a
lambda parameter, a match-arm pattern variable) must be gensym'd automatically —
**without** an author writing `<fresh …>` — together with every reference the
template makes to that binder, so:

- a template binder can never **capture** a use-site name the caller passes in,
  and a caller's binder can never capture a template reference; and
- `<capture Name>` is the opt-out: it marks a binder the author *wants* visible
  in caller scope (the deliberate, on-demand escape hatch).

The two exploitable holes (a) and (b) are already closed for the explicit path;
this plan generalises that guarantee to the *implicit* (unannotated) path, which
is where real macros live.

## 2. Current state (grounded, verified in tree)

- `<fresh Name>` parses only as an explicit prefix marker in the `:lt` window at
  `parser.ex:2041-2046` → `{:fresh_name, meta, name}`.
- `expand_template_rule` (`parser.ex:1142`) runs `freshen(template, state, true,
  bindings)` **before** `subst_holes`, so use-site material is never freshened.
- `freshen/4` (`parser.ex:1270`) collects `collect_fresh_names/1` (ONLY
  `{:fresh_name,…}` markers), mints one gensym per name via `mint_gensym/3`
  (collision-avoidance vs. `collect_used_names(bindings)` — the gap-(b) fix), and
  rewrites via `apply_freshening/4`.
- `apply_freshening/4` (`parser.ex:1381+`) is a **flat** rewrite: a
  `{:fresh_name}` marker → its gensym var; a plain `{:variable}` whose name is a
  declared fresh name → its gensym **unless** the name is a hole (the gap-(a)
  fix leaves holes untouched). It has **no notion of lexical scope** — it renames
  by global name-match, which is correct only because today the sole source of
  freshened names is explicit unique markers.

**Binder shapes a template can contain** (verified):
- `let` → `{:assignment, meta, [pattern, value]}`, desugared into a
  `{:block, meta, [assignment, body]}` (`parse_let/1`, `parser.ex:3177-3230`).
- match arm → `{:match_arm, [pattern: p], [body]}` (pattern lives in **meta**,
  `parser.ex:3594`); with-rematch arms stash `:parent_patterns` in meta.
- lambda parameters and fn-clause params (confirm exact tuple in Task 0).

**Implication:** the flat rename cannot be reused as-is for auto-hygiene. Auto
mode introduces MANY binders whose names may legitimately recur and shadow, so
rename correctness now depends on **which binder lexically binds a reference** —
a scope-aware walk, not a global name-match.

## 3. Design fork (prose, per operator directive; recommend the lower-risk option)

**Option A — full set-of-scopes (Flatt / Racket).** Attach uncopyable scope
marks to every identifier; hygiene falls out of scope-set resolution. This is
the "align with a real language" ideal and is the model the SP5.3 spec text
names. **Cost/risk: HIGH** — it changes the identifier representation across the
parser and every consumer, is a large rewrite, and churns a broad test surface.
Its one *strictly* greater power over Option B is hygiene that survives
**serialization across module boundaries** (scope identity as data), which
matters for **SP5.2 cross-module macro import** — a *separate* sub-project.

**Option B — template-scoped binding-position auto-freshening (RECOMMENDED).**
Keep the string-gensym substrate, but (1) discover binder names from binding
positions in the template automatically, and (2) replace the flat
`apply_freshening` with a **scope-aware walk** that pushes a rename frame at each
binding form, renames a binder + only the references it lexically binds, honors
shadowing, and leaves free references (holes / caller-scope names) untouched —
reusing the already-built `mint_gensym` collision-avoidance and hole-exclusion.
`<capture Name>` opts a binder out. **Same observable gate, lower risk.**

**Why B, not A, now.** The two *exploitable* holes set-of-scopes was invoked to
close (a: same-name-hole; b: backtick gensym-spoof) are **already closed** by
the collision-avoidance + hole-exclusion machinery — so the residual case for A
is no longer "soundness," it is only cross-module scope-identity, which belongs
to SP5.2. Operator standing directive: *when the difference is just semantics,
prefer the lower-risk option.* B and A are observationally identical for
single-module hygiene (the SP5.3 gate). **Decision: implement B now; record A as
the deferred upgrade, to be revisited iff SP5.2 proves it needs serializable
scope identity.** (If SP5.2 later needs A, B's scope-aware walk is the natural
place it slots in — no rework is wasted.)

## 4. The crux (prototype/verify early)

**Scope-correct reference resolution inside a template.** A reference renames to
the binder that *lexically* binds it, honoring shadowing (`let x = 1 in let x =
2 in x` → inner `x`), while a **free** reference — one no template binder binds —
is left alone (it is either a hole about to be substituted, or a genuine
caller-scope name). Set-of-scopes gets this for free; Option B must implement a
small lexical-scope walk. **Verify in Task 0 with a scratch probe** that the walk
renders each of: capture-avoidance, shadowing, free-var passthrough, and
`<capture>` opt-out — before wiring it into `freshen`.

## 5. Tasks (strict red-green; commit per task, ghost author, explicit pathspec)

### Task 0 — grounding probes (no commit)
Dump the parsed template AST for: `let x = e in b`; a lambda with a param; a
`match … | P(x) -> x`; a nested-shadow `let x = 1 in let x = 2 in x`. Record the
exact binder tuples (esp. lambda-param and fn-clause shapes not yet pinned in
§2) in this plan's Task-2 anchor before writing code. Confirm which of these the
`becomes` template grammar can actually produce.

### Task 1 — RED fixtures (`test/cure/compiler/macro_hygiene_test.exs`)
Add, all initially red (auto mode not yet implemented), each a behavioral
assertion on expanded output:
1. **auto-capture-avoidance:** rule `syntax m becomes let acc = 0 in acc` used
   where the caller has its own `acc` in scope — the template's `acc` binder is
   gensym'd, distinct from the caller's `acc`. (Today: plain `acc`, would
   capture.)
2. **shadowing:** `becomes let x = 1 in let x = 2 in x` — the trailing `x`
   resolves to the *inner* gensym; the two binders get *distinct* gensyms.
3. **free-var passthrough (gap-(a) regression):** a plain template reference that
   is a **hole** is still substituted, not freshened (re-assert the existing
   `shadow`/`cap` invariants hold under auto mode).
4. **`<capture Name>` opt-out:** `becomes let <capture done> = true in done` —
   `done` is NOT freshened; it binds into caller scope (a following caller
   reference to `done` sees it).
5. **lambda param** auto-freshened; **match-arm pattern var** auto-freshened.

### Task 2 — binder discovery (`collect_binder_names` per scope)
A pass identifying template-introduced binder names by AST shape
(assignment-LHS variables, lambda params, match-arm pattern vars), EXCLUDING
hole names and `<capture>`-marked names. Feeds the rename-frame minting.

### Task 3 — scope-aware freshening walk
Replace the flat `apply_freshening/4` rename with a scoped walk carrying a stack
of rename frames: at each binding form, mint gensyms (via existing
`mint_gensym/3`, so collision-avoidance + gap-(b) hold) for its non-`<capture>`
binders, push a frame, rewrite the binder + references it binds within its body,
pop on exit. Free references fall through unchanged (holes handled exactly as
today). Explicit `{:fresh_name}` markers keep their current behavior (Task 5).

### Task 4 — `<capture Name>` marker
Parse a `<capture Name>` prefix marker symmetric to `<fresh Name>`
(`parser.ex:2041`) → `{:capture_name, meta, name}`. In the auto pass it lowers to
a plain caller-scope `{:variable}` that the freshening walk leaves untouched.

### Task 5 — reconcile explicit `<fresh>` (back-compat)
With auto-hygiene on, explicit `<fresh Name>` is redundant but MUST remain
accepted and behave identically (it is now just an explicit spelling of the
default). Keep the existing `<fresh>` tests green unchanged.

### Task 6 — existing-template audit (RISK GATE)
Auto-freshening changes the default for EVERY landed `becomes` template. Audit
the stdlib + test macros (esp. the structured OTP families) for any template
binder that *intentionally* binds into caller scope; convert those to
`<capture>`. **A template that relied on an un-freshened binder leaking into
caller code will break without this.** Scoped `mix test` per touched area.

### Task 7 — Stage 6 gate
Full `mix test` once, alone. Update the running state file noting SP5.3 complete
(both correctness holes + auto-hygiene default), and mark SP5.3 done in the
program roadmap §2/§5.3.
