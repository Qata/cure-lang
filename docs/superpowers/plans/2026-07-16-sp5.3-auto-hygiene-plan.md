## 1. The gate (from `2026-07-12-macro-facility-program.md` / REMAINING-WORK §5.3)

> "auto-hygiene renames template binders with no annotation; `<capture>` still
> binds into caller scope on demand; full suite green."

Concretely: in a Tier-2 `becomes` template, an identifier in an **ordinary
lexical binding position** that the template introduces (a `let`/assignment LHS,
an expression-position lambda parameter, a match-arm pattern variable, a
comprehension binder) must be gensym'd automatically — **without** `<fresh …>` —
together with every reference the template makes to that binder, so a template
binder can never capture use-site material and vice versa. `<capture Name>` is
the on-demand opt-out.

## 2. Current state (grounded, verified in tree)

- `<fresh Name>` parses only as an explicit prefix marker in the `:lt` window at
  `parser.ex:2041-2046` → `{:fresh_name, meta, name}`.
- `expand_template_rule` (`parser.ex:1142-1144`) runs `freshen(template, state,
  true, bindings)` **before** `subst_holes`, so use-site material is never
  freshened. **This ordering is load-bearing and is the crux of §4's boundary.**
- `freshen/4` (`parser.ex:1270`) collects `collect_fresh_names/1` (ONLY
  `{:fresh_name,…}` markers), mints one gensym per name via `mint_gensym/3`
  (collision-avoidance vs. `collect_used_names(bindings)` — the gap-(b) fix), and
  rewrites via `apply_freshening/4`.
- `apply_freshening/4` (`parser.ex:1381+`) is a **flat, tuple/list-only** rewrite:
  it recurses into `{t, meta, ch}` when `is_list(ch)` and into list values, and
  **falls through every other shape untouched** — in particular **raw Elixir
  maps** and **string children** (`apply_freshening_value/4`,
  `parser.ex:1416-1422`; same for `collect_fresh_names_*`). It has **no notion of
  lexical scope** — correct today only because the sole freshened names come from
  explicit unique markers.

**Binder shapes a template can contain** (verified in tree):
- `let` → `{:assignment, meta, [pattern, value]}`, desugared into
  `{:block, meta, [assignment, body]}` (`parse_let/1`, `parser.ex:3177-3230`).
  **The LHS `pattern` is a general `parse_expr(_,6)` result** — it may be a
  destructuring pattern (`{a,b}`, records, constructors), not just a bare
  `{:variable}`.
- match arm → `{:match_arm, [pattern: p], [body]}` (pattern in **meta**,
  `parser.ex:3594`); with-rematch arms stash `:parent_patterns` in meta
  (`parser.ex:3707-3744`) — the existing `collect_fresh_names_meta` comment
  (`parser.ex:1355-1358`) already documents that markers hide there.
- comprehension/generator → `{:generator, [], [pattern, collection]}`
  (`parser.ex:2822-2875`) — `pattern` binds names.
- **lambda / fn params have THREE incompatible representations** (review-confirmed):
  1. **expression-position anonymous lambda** — `params:` meta is a plain list of
     **strings** (`parser.ex:4793-4815`); body is real AST. → **IN scope**, needs
     meta-string handling (§5 Task 3).
  2. **multi-clause `def`** — `:clauses` meta is a list of raw **maps**
     `%{params: patterns, guard:, body:}` (`parser.ex:4338/4407`). → **OUT** (§4).
  3. **single-clause `def`/`callback` typed params** — `{:param, meta, name}` with
     `name` a **string**, inside the `:callbacks`/`:params` **map**
     (`parse_lift_callback`, `parser.ex:5903-5922`; `parameter_names` derived by
     verbatim string at `:5914`). → **OUT** (§4).

## 3. Design fork (prose; RECOMMEND lower-risk Option B — review confirmed sound)

**Option A — full set-of-scopes (Flatt / Racket).** Uncopyable scope marks on
every identifier; hygiene falls out of scope-set resolution. The spec-named
ideal, and the model needed for hygiene that survives **serialization across
module boundaries** (SP5.2 cross-module macro import). **Risk: HIGH** — changes
the identifier representation across the parser and every consumer; large
rewrite; broad test churn.

**Option B — template-scoped binding-position auto-freshening (RECOMMENDED).**
Keep the string-gensym substrate; auto-discover ordinary binder names from
binding positions and replace the flat `apply_freshening` with a **scope-aware
walk** (rename frames pushed at each binding form; rename a binder + only the
references it lexically binds; honor shadowing; leave free refs — holes /
caller names — untouched), reusing `mint_gensym`'s collision-avoidance +
hole-exclusion. `<capture Name>` opts a binder out. Same observable gate,
lower risk.

**Soundness of the fork — CONFIRMED by Stage-3 review (`a23355a3`).** The
reviewer tried and **could not** construct a single-module program where Option
B diverges from set-of-scopes given a correctly-implemented walk: `fresh_counter`
is a single **globally-monotonic** counter threaded through parser state
(`parser.ex:1290-1299`), so two mints — across nested expansion, sibling
invocations, or an inner expansion flowing into an outer hole — **cannot**
collide by construction (not by luck); and `collect_used_names` (gap-(b))
already defends caller spoofing within an invocation. The two *exploitable* holes
A was invoked for are already closed. A's only strictly-greater power
(serializable cross-module scope identity) belongs to **SP5.2**. **Decision:
implement B now; record A as the deferred upgrade, revisited iff SP5.2 needs
serializable scope identity.** B's scope-aware walk is exactly where A would
later slot in — no rework wasted.

## 4. SCOPE BOUNDARY (the FATAL finding, resolved) — what auto-hygiene does and does NOT touch

Auto-hygiene applies to a binder **iff** (i) it sits in the **ordinary
expression grammar** (proper AST tuples/lists), AND (ii) its **scope body is
real AST at freshen time**. This is precisely the set the tuple/list walk can
reach and rename soundly.

**IN scope** (this slice): `let`/assignment binders (block-body scope);
match-arm pattern binders (arm-body scope); with-rematch `:parent_patterns`;
comprehension/generator binders; expression-position anonymous-lambda params
(shape 1). For patterns, **every variable leaf** of the LHS/pattern tree is a
binder (destructuring `let {a,b} = …` binds both `a` and `b`).

**OUT of scope — DEFERRED, documented, and POSITIVELY TESTED as a no-op**:
structured-family / `def`-**signature** binders — the `:callbacks` and `:clauses`
**maps** and their `{:param, _, name}` entries (shapes 2 & 3). **Why they are
excluded, not merely unhandled:**
1. They live in raw Elixir **maps**, which the freshening recursion never walks —
   so today they are untouched, and this slice **must keep them untouched**.
2. In `becomes lift module` templates the callback **body is a delayed-raw hole**
   resolved *after* `freshen` (inside `subst_holes` via
   `subst_lift_module_value`/`resolve_delayed_raw`, `parser.ex:1577-1622`), and it
   binds its signature params by **verbatim name-match** against
   `callback_context.parameter_names` (`parser.ex:5914`). Renaming a signature
   param at freshen time therefore **cannot** propagate into a body that is not
   yet AST — it would silently break every `%[:reply, :ok, state]` /
   `%[:noreply, state]` clause across `Std.Actor/Fsm/Supervisor/App`
   (`lib/std/actor.cure:77-148` et al.). This is a signature-binds-body closed
   unit under the family expander's control, not a caller-capture hazard.
3. `<capture>` cannot even be *written* on such a param: `parse_typed_params`
   (`parser.ex:4572-4616`) reads a raw identifier token with no `parse_expr` hook
   for a `<capture …>` prefix.

**Consequence for the design:** the walk **must NOT add map-walking**. Keeping
the recursion tuple/list-only is what makes family-signature binders a guaranteed
no-op. Hygiene for family-signature params is a **separate follow-on concern**
(tie to family/OTP hygiene, plausibly folded with SP5.2 or its own slice) — named
here as a known limitation, out of SP5.3's DONE bar.

## 5. Tasks (strict red-green; commit per task, ghost author, explicit pathspec)

### Task 0 — grounding probes (no commit) — WIDENED per review
Dump the parsed template AST for EACH of: `let x = e in b`; **destructuring**
`let {a,b} = p in a`; nested-shadow `let x = 1 in let x = 2 in x`; an
expression-position `fn(y) -> y+1`; `match … | P(x) -> x`; a comprehension
`[y*2 for y in xs]`; a with-rematch arm; **and a `becomes lift module` with a
`callback`/multi-clause `fn`** (to confirm §4's OUT set is map-shaped and
delayed-raw). Record the exact binder tuples in Task-2's anchor before code. If
any IN-scope shape turns out to be map-/string-backed like the OUT set, STOP and
re-scope — Task 0 exists to catch exactly the surprise that produced v1's FATAL.

### Task 1 — RED fixtures (`test/cure/compiler/macro_hygiene_test.exs`)
All initially red, behavioral assertions on expanded output:
1. **auto-capture-avoidance:** `syntax m becomes let acc = 0 in acc` where the
   caller has its own `acc` — template `acc` is gensym'd, distinct.
2. **shadowing:** `becomes let x = 1 in let x = 2 in x` — trailing `x` → inner
   gensym; the two binders get distinct gensyms.
3. **destructuring LHS:** `becomes let {a,b} = pair in a` — both `a` and `b`
   auto-freshened; reference to `a` tracks its gensym.
4. **free-var passthrough (gap-(a) regression):** a plain template reference that
   is a **hole** is still substituted, not freshened.
5. **`<capture Name>` opt-out:** `becomes let <capture done> = true in done` —
   `done` NOT freshened; binds into caller scope.
6. **expression-lambda param** and **match-arm pattern var** auto-freshened.
7. **OTP no-op (positive boundary lock):** a `becomes lift module` template with a
   `callback`/`fn name(p: T)` signature — assert the signature param name is
   **unchanged** after expansion (auto-hygiene is a no-op on §4's OUT set). This
   pins the boundary so a future executor can't silently "generalize" into it.

### Task 2 — binder discovery (`collect_binder_names`, IN-set only)
Identify template-introduced binder names by AST shape for the §4 IN set —
**every variable leaf** of assignment-LHS / match / generator / with-rematch
patterns, plus expression-position lambda `params` strings — EXCLUDING hole names
and `<capture>`-marked names, and **never descending into `:callbacks`/`:clauses`
maps** (assert this).

### Task 3 — scope-aware freshening walk (UNIFIED with `<fresh>`)
Replace the flat `apply_freshening/4` with a scoped walk carrying a stack of
rename frames: at each binding form, mint gensyms (via existing `mint_gensym/3`)
for its non-`<capture>` binders, push a frame spanning that form's body, rewrite
binder + references it binds, pop on exit; free refs fall through (holes handled
as today). **`<fresh Name>` markers fold INTO this walk** as a frame spanning
"rest of template" (matching today's template-global behavior) — ONE unified
pass, explicit precedence, so a template mixing `<fresh x>` with an
auto-discovered `let x` has a defined result (Task 5 locks this with a test).
Expression-position lambda `params` (string list in meta) get a dedicated
meta-aware case; **maps are still not walked** (§4).

### Task 4 — `<capture Name>` marker
Parse `<capture Name>` symmetric to `<fresh Name>` (`parser.ex:2041`) →
`{:capture_name, meta, name}`, lowering in the walk to a plain caller-scope
`{:variable}` the walk leaves untouched. (Applies only to expression-grammar
binders; §4 OUT binders are unreachable by design and need no marker.)

### Task 5 — reconcile explicit `<fresh>` (back-compat + mix rule)
Keep all existing `<fresh>` tests green unchanged. Add one test for a template
mixing `<fresh x>` and auto-discovered `let x = …` asserting the Task-3
precedence rule holds (no cross-binding to the wrong gensym).
