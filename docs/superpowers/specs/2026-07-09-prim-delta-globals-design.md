## §1 Locked design decisions

1. **Builtin-op def-kind, registry-keyed (kills risk R1).** Ops are seeded as BODY-LESS defs carrying a `builtin_op` marker in the def record (mechanism analogous to `Inductive.register_builtin`, inductive.ex:119-137), registered under stable keys. EVERY consumer — the Normalise compute hook, emit's inline, GuardLint's Z3 translation — resolves through the def record/registry, NEVER bare global names. Rationale: `qualified_syms` is `:off` and cross-module global collision is a known gap; a user def named `add` must not be delta-computed (kernel unsoundness), Z3-translated (lint unsoundness), or operator-inlined (miscompile). Emit's existing `connective_inline` (emit.ex:216-244) keys on bare atoms — a pre-existing smell for canonical prelude names; NOT copied, NOT fixed here (noted for follow-up).
2. **Compute hook in the certified-δ engine.** `unfold_certified_head` (normalise.ex:196-244) gains a builtin-op branch: head is a builtin-op def AND every spine arg whnfs to a literal value → compute via the EXISTING audited fold table (`Eval.fold`, eval.ex:102-142, extracted to a shared home so Eval and Normalise call one table); otherwise stay stuck (§G.1 rule 1 preserved verbatim — div/rem by literal zero remains neutral). Builtin-op defs are **certified-by-construction**: `Env.certified?` answers true for them (or the gate branches before the body check) — they have no body and no termination question (no self-calls; size-change treats them as terminal). `Conv`'s lazy-δ inherits the hook through the same engine; `same_neutral_no_delta?` loop-safety is trivial (no body to loop on).
3. **Monomorphic per-type op globals (Lean-aligned).** `infer_prim`'s ad-hoc polymorphism (add/sub/mul/div numeric-polymorphic, eq/ne any-shared-type) is NOT reproduced. The seeded set is monomorphic pairs, exactly the ops with live producers: `int_add/int_sub/int_mul/int_div/int_rem/int_lt/int_le/int_gt/int_ge/int_eq/int_ne : Int -> Int -> {Int|Bool}` and `float_add/float_sub/float_mul/float_div/float_lt/float_le/float_gt/float_ge/float_eq/float_ne : Float -> Float -> {Float|Bool}` plus `int_neg/float_neg` (unary; `neg` is produced only by core_bridge today). The ELABORATOR type-directs the choice (it already type-directs `==` via `primitive_scrut_kind`/`bool_operand?`, elaborator.ex:634-665): Bool operands keep routing to the Std.Bool case-defs (unchanged); Int → `int_*`; Float → `float_*`; underdetermined/other operand types → elaboration error naming the operator (today's prim would have been typed-then-stuck anyway; the honest surface is a type-directed reject — any surface program this newly rejects is a STOP-and-report for adjudication, expected count ZERO since eq/ne on non-numerics never folds today and no oracle fixture exercises it — the plan must verify that claim with a corpus survey before flipping). Zombie `and/or/not` prims are NOT seeded (kernel already rejects them; core_bridge stops producing them — its Bool folding already lives surface-side in `fold_bool_binop`, reduce.ex precedent).
4. **The types-pipeline carve-out is pre-authorized NOW (D2 §8 precedent, not re-litigated mid-run):** `lib/cure/types/core_bridge.ex` (to_core prim producers :54-70, from_core inverses :143-147) and `lib/cure/types/reduce.ex` are Core-grammar CONSUMERS. `to_core` produces builtin-op global spines (registry-consistent atoms); `from_core` reads them back; `reduce.ex`'s `kernel_normalize_via_core` (:98-99) switches from sig-free `Eval.eval([])` to the kernel's signature-carrying normalization over a builtins-seeded env, so classic-pipeline constant folding KEEPS working AND keeps its "no arithmetic folded outside Cure.Core" design contract (kills risk R2 the principled way — the Bool-style private-fold fallback is the rejected alternative). Behavior-pinned by the classic Reduce/Equality tests with assertions untouched. NOTHING ELSE under `lib/cure/types/`/`lib/cure/compiler/` changes.
5. **Emit: registry-keyed saturated inline + eta-wrapper for first-class use (kills R7).** Saturated builtin-op spines lower to the SAME BEAM operators as today (erl_binop/erl_unop tables, emit.ex:296+; inline precedent: D2's `sigma_first/second → element/2`, emit.ex:236-241 — but keyed via the registry per decision 1, not bare atoms). An UNSATURATED reference to a builtin-op global emits a local fun wrapper (`fun(A, B) -> A + B end`) so first-class/HOF use — newly possible — actually runs. Runtime behavior of every existing program is bit-identical.
6. **GuardLint retarget (the pre-recorded coupling):** `bool_form`/`int_form` (guard_lint.ex:93-125) gain one clause each recognizing SATURATED builtin-op spines, resolved through the def record (per decision 1 — a user's own `add` is NOT translated; it falls to the sound uninterpreted-atom fallback). The `{:prim,…}` clauses are stripped with the node. The lint-soundness argument (never-over-prove) is unchanged; the Antigen drop_guard flip pin keeps patrolling it.
7. **Two-phase coexistence, then strip (the established ratchet):** Phase 1 — seed the builtin-op defs + compute hook + signatures; `{:prim}` still fully live (both representations coexist; kernel unit-provable in isolation). Phase 2 — flip every producer (elaborator `build_binop` :641-652, literal-pattern chain :2664, core_bridge, Antigen `surface_expr`), retarget GuardLint + emit + Reduce. Phase 3 — strip `infer_prim`, Eval's prim clause, `{:nprim}` neutral handling (value/normalise/conv/quote), term.ex grammar, serialize enc/dec, validator children; flip `no_prim_node` → `:reject` (wave0 AND release; also FIX the recorded doc/code drift — spec §J and the audit say `:off` while validator.ex:57 has `:warn`; the ledger note corrects the docs); retarget remaining Antigen generators and pins. At no point does a green build smuggle prim nodes past a half-stripped kernel.
8. **Type-level computed indices (R3) are preserved by construction:** open `{:prim,:add,[v,v]}` inside data indices (Antigen dep_match.ex:105 seeds this) becomes an open builtin-global spine — compared by the GENERIC neutral app-spine congruence instead of the bespoke `{:nprim}` clause. Same judgement strength: both are syntactic spine congruence for open terms; closed terms fold in both worlds. The Antigen conv/dep_match retargets pin this equivalence.
9. **Error-shape churn is enumerated, not silent (R5):** `{:prim_type, op}`/`{:unknown_prim, op}` vanish with `infer_prim`; every pin flips to the ordinary global-application error shapes, each flip justified per the C-3 discipline. The serialize conformance fixture's `(prim …)` rows re-spell as builtin-global-app rows (accept) and stay-reject equivalents.
