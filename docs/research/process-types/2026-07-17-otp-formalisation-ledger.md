NEW machinery: **`bool_mt`, a boolean modus-tollens** (`(b=T ⟹ c=T)` and `c=F` force `b=F`), which refutes the transitivity's reverse leg `¬(w ≤ u)` WITHOUT boolean blindness — were `w ≤ u`, then `w ≤ v` by `vc_le_trans`, contradicting `¬(w ≤ v)`. `bool_mt` must be stated with the **convoy pattern** (match the boolean, RETURN a function of the implication hypothesis) because a plain `match b` does not refine a sibling hypothesis whose type mentions `b` (the sort_unique lesson; in Idris the clause-based match refines it directly, so `boolMt` is flat/curried there — same type). Then the operational leg: `tick_strict` proves `v ≺ tick(i,v)` — a local event ticks the process's own component and strictly advances the clock — using an inductive `InRange(i,v)` witness that the index is within the clock's dimension (so the tick genuinely changes a component; `tick_gt` shows the ticked clock is not `≤` the old one via `leq_succ_self_f`). So successive events on ONE process are strictly ordered by their clocks — the program-order soundness of vector clocks. Idris `rel=same`.
- [x] **THE CLOCK CONDITION — Fidge–Mattern SOUNDNESS** (`fidge_mattern.cure`): the capstone of the logical-time development. Causal precedence (Lamport happens-before) is modelled INDUCTIVELY over clock-stamped events by `HB(a,b)`, generated by the two OPERATIONAL rules — `HBTick` (a local event: `HB(v, tick(i,v))` with an `InRange` witness — program order) and `HBRecv` (a receive that merges the sender's timestamp then ticks: `HB(m, tick(j, vmax(v,m)))` — message order) — closed under `HBTrans`. `hb_sound` proves `HB(a,b) ⟹ vc_lt(a,b) = T`: if event a causally precedes b, its vector clock is STRICTLY less. So comparing timestamps SOUNDLY detects causality — if `VC(a) ⊀ VC(b)` then a did NOT cause b, the basis of vector-clock causality tracking in distributed / BEAM systems. The proof composes the ENTIRE logical-time corner: the local leg is `tick_strict`; the receive leg chains sender's-stamp-≤-merge (`vmax_ub_r`) with merge-≺-ticked-clock (`tick_strict`) via a new mixed-transitivity lemma `le_lt_trans` (`m ≤ a ∧ a ≺ b ⟹ m ≺ b`, itself using `bool_mt`); the transitive closure is `vc_lt_trans`. This is the standard, cleanly-provable half of the Fidge–Mattern characterization; the converse COMPLETENESS direction (`VC(a) < VC(b) ⟹ a → b`, which needs the clock to encode enough per-process history) is the deeper open direction, noted for a future probe. Idris `rel=same`.
- [x] **Async restart must FLUSH the in-flight buffer** (`restart_orphan.cure`): on the async dimension, a config carries a message buffer (`BEmpty`/`BFull`). `flush_is_fresh` proves resetting both participants to duals AND emptying the buffer is a well-formed fresh session for every protocol; `noflush_orphans` proves resetting the locals but KEEPING a non-empty buffer `BFull(m)` leaves the config not-fresh for every protocol — the buffered message is an ORPHAN no fresh participant awaits (helper `noflush_orphans_tail` cases the stuck `compatible` so `andb(x, False)` reduces). So a correct restart of an async session flushes its buffer, not merely resets protocol state — ties async orphan-freedom to the restart action.
- [x] **Lifecycle termination × session completion (conservation)** (`session_lifecycle.cure`): a gen_server carries a session and performs one callback per protocol message; a run fragment `Serve(pre, post)` drives the state. `conservation` proves `run_len(s) + proto_len(post) = proto_len(pre)` — steps taken plus obligations remaining equals the total protocol length, by induction (each step decrements remaining and increments count in lockstep). Corollary `complete_run`: a run reaching `LEnd` performs EXACTLY `proto_len(pre)` steps — every session obligation discharged once, none skipped (no stuck/deadlocked server) or doubled. The `Terminated(l)` index enforces NORMAL-stop-only-at-`LEnd` (`clean_shutdown`) while `TCrash` may stop at any state (`crash_anytime`) — the lifecycle asymmetry. FINDING: Idris auto-bound implicits are erased (multiplicity 0), so threading `post` through the recursive proof gives `post is not accessible`; explicit `{pre : Local} -> {post : Local}` named-implicit binders fix it (faithful — same theorem). Idris `rel=same`.
- [x] **Supervised-session liveness — progress completes or intensity abandons** (`session_liveness.cure`): ties restart INTENSITY to session PROGRESS in one shared state `Run(orig, cur, budget)`. A PROGRESS event advances `cur` toward `LEnd` (→ `Completed`), a CRASH resets `cur` to `orig` and consumes budget (→ `Abandoned` at zero). `progress_completes` (`S(proto_len cur)` progress steps reach `Completed` — a progressing session terminates in success, induction on the protocol, message-agnostic) and `crash_abandons` (`S(budget)` crashes reach `Abandoned` — a persistently-crashing session exhausts its restart intensity and is abandoned, never retried forever, induction on budget), plus all four cross-absorbing lemmas (`Completed`/`Abandoned` ignore a spurious crash/progress — no resurrection under either event). So a doomed supervised session cannot loop forever: it either completes or is abandoned. Idris `rel=same`.
